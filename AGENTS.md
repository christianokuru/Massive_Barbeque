# AGENTS.md — Massive Barbeque

Nuxt 4 (Nitro) BBQ ordering app. Frontend in `app/`, file-based Nitro routes in `server/api/`, Supabase (Postgres + Auth) via `server/utils/supabase.ts`. Pricing helpers in `shared/utils/pricing.ts`. Deep reference: `docs/codebase.md` (full route/component/DB catalog + known bugs); live ops: `docs/payment-webhooks.md`; per-session work logs: `docs/worklog/` (where past work stopped — read the latest entry first).

## Commands (npm only — lockfile is `package-lock.json`)

- `npm install` then `npm run dev` (http://localhost:3000). No `postinstall` script — if `.nuxt/` types are missing, run `npx nuxt prepare`.
- Verify with `npm test` (vitest, hermetic unit-only — no Supabase/network); single suite: `npx vitest run tests/pricing.test.ts` (`tests/`: pricing, rateLimit, orderStatus, cartStore, siteUrl, adminGovernance). No lint, typecheck, or CI — vitest is the only check. Never run `npm run build` unless asked.
- DB lives in Supabase: schema in `supabase/migrations/` (`0001` schema, `0002` category parents, `0003` governance — RLS on, zero policies, service-role only); seed with `node supabase/seed.mjs` (idempotent upserts on slug/sku; parses `.env` itself for `SUPABASE_URL` + `SUPABASE_SERVICE_ROLE_KEY`). No local migration runner.

## Env

- `.env` is gitignored — never commit it; key names live in `.env.example`.
- Server reads keys via `useRuntimeConfig()` (`nuxt.config.ts`). `SUPABASE_SERVICE_ROLE_KEY`, `PAYSTACK_SECRET_KEY`, `FLUTTERWAVE_SECRET_KEY`, `RESEND_API_KEY` are server-only; only `runtimeConfig.public.*` (`NUXT_PUBLIC_*`) reaches the client.

## Structure

- Pages (`app/pages/`): `index`, `menu`, `product/[id]`, `about`, `contact`, `checkout`, `checkout/confirm`, `login`, `register`, `forgot-password`, `reset-password`, `dashboard/` (index, orders, orders/[id], profile), `admin/` (index, orders, orders/[id], products, admins — `products.vue` is a single page + dialog, no `products/new`). Layouts (`app/layouts/`): `default`, `dashboard`, `admin`, `auth` (bare + AuthShell).
- Components: `custom/landing/` is the live homepage (used by `index.vue`); `custom/Home/` + `useProjects.ts` are unused legacy — don't build on them. Shop UI in `custom/{ecommerce,product,admin}/` (ProductCard, CartItem, OrderStatus, OrderTable, `admin/products/` ProductDialog/AdminProductCard); `custom/general/` is live shared UI (Navbar, Footer, NavSheet, CartSheet, AuthShell). `app/components/ui/` = shadcn-vue (`new-york`, `typescript: false`, lucide); `nuxt.config.ts` ignores `ui/**/index.*` in auto-scan (barrels would register as colliding `Ui*` components) — keep importing those explicitly.
- SFCs mix plain `<script setup>` and `<script setup lang="ts">` — match the surrounding file.
- Client state: `useAuth.ts` (`isAdmin` from `app_metadata.role`; `isOwner` from `GET /api/auth/session`, not the JWT), `useSupabase.ts`, `useAdminProducts.ts`. Cart is local-first: `app/composables/useCart.ts` + `cart/{types,storage,ops}` (pure ops, localStorage-persisted, zero network until checkout). Checkout posts `{variantId, quantity}[]`; `orders.post.ts` reprices from the live catalog and writes via service role (no customer order-insert RLS policy — identity from session, money from DB, never the client). Guest order reads use service role + code authz in `orders/[id].get.ts` (owner/admin/`user_id` null). There are no `/api/cart*` routes. Styling is Tailwind v4 (`@import "tailwindcss"` in `app/assets/css/main.css` via `@tailwindcss/vite`; no `tailwind.config`) with M3 tokens — see `MATERIAL-3-DESIGN-PRINCIPLES.md` for UI work. `colorMode` is dark-only (`preference: "dark"`, `fallback: "dark"`, `storageKey: "massive-theme"` — no light mode, no theme toggle).
- Mobile-first: base styles for small screens, `sm:`/`md:`/`lg:` up; never ship desktop-only layouts.
- Client plugins must be `*.client.ts` (`app/plugins/`: aos, lenis, flutterwave, supabase). Lenis resets scroll on `page:finish`. Lenis owns window scroll — any modal/sheet MUST pair it with `lenis.stop()`/`start()` plus body `overflow` lock (see `setScrollLock` in `Navbar.vue`, same pattern in `ProductDialog.vue`), or the background keeps scrolling behind the overlay.
- API: `server/api/**/*.get|post|put|delete.ts` (`orders.post.ts` vs `orders/[id].get.ts` pattern). Subdirs: `auth/`, `products/`, `categories/`, `orders/`, `contact.post.ts`, `payments/{paystack,flutterwave,webhooks}/`, `admin/{admins,orders,products,variants,customers}/`. Use `getSupabase(event)` (user-scoped, RLS applies) for user data; `getServiceSupabase()` bypasses RLS — admin/webhook-only, plus order create/read (no customer RLS policies there; authz in code). Admin product image upload is multipart → `product-images` bucket, 5MB max (`admin/products/images.post.ts`).
- Pricing: `shared/utils/pricing.ts` is the single source (`DELIVERY_FEE_FLAT = 2000`, `orderTotals`/`deliveryFeeFor`, `toAmount` for Postgres `decimal` strings, `toKobo` for Paystack). Both `server/api/orders.post.ts` and checkout use it — never hardcode the fee on either side. Status enums + `canTransitionOrder` live in `shared/utils/orderStatus.ts` — reuse them for status logic (note: the admin status PUT validates the enum only, it doesn't enforce transitions).

## Gotchas

- `PROJECT_SCOPE.md` is the fuller re-onboarding doc but has stale bits (e.g. claims a `postinstall` script — `package.json` has none); `README.md` is the stock Nuxt starter; `PRD.md` is historical batch notes. Trust executable sources (`supabase/migrations/`, `server/api/`, `nuxt.config.ts`, `.env.example`). Live ops notes live in `docs/payment-webhooks.md` (admin governance, webhook deploy checklist, paid-but-stuck reconcile).
- Nuxt 4 `~/` resolves to `app/`, so server code must import via `~~/server/...` (e.g. `~~/server/utils/supabase`), never `~/server/...` — the latter breaks the Nitro build. Shared helpers are `~~/shared/...` from both server routes and app code (e.g. `useCart.ts`).
- Auth: Supabase Auth email/password, `@supabase/ssr` cookie session — never roll custom cookies. Admin role lives in `app_metadata.role`; `ADMIN_EMAILS` allow-list promotes on sign-up/sign-in (`server/utils/adminBootstrap.ts`, supports `admin_invites` table) — no in-app self-promotion. Owners (`OWNER_EMAILS`, fallback `ADMIN_EMAILS`) manage admins at `/admin/admins` (`GET/POST/DELETE /api/admin/admins`, `requireOwner`-guarded, audited) — sticky until explicitly demoted, nobody can demote themselves, owners env-only, see `docs/payment-webhooks.md`. Register treats duplicate email as sign-in attempt (password must still match — don't "fix" this). Login returns 404 for unknown email (enumerable by design, throttled) vs 401 for wrong password — keep that shape. Rate-limited (`server/utils/rateLimit.ts`, in-memory single-instance): login 10/15min, register 5/hr, orders 20/15min, contact 5/hr, pay-init 30/hr, pay-verify 60/hr, admin-promote 20/hr per IP.
 - Guards: API `requireUser`/`requireAdmin`/`requireOwner` (deny missing roles, never fail open); pages `app/middleware/auth.ts` (dashboard) and `admin.ts` (guests → `/login?redirect=`, non-admins → `/`) — both server-safe via `/api/auth/session`. Login/register pages only honor internal `redirect` (`startsWith("/")` and not `"//"`); default landing is `→ /menu` for customers (`→ /admin` for admins). `useAuth.fetchSession` reads `GET /api/auth/session` (httpOnly-safe) and `app/app.vue` hydrates it globally on mount so Navbar/auth links stay correct after gateway returns. Security headers in `nuxt.config.ts` `routeRules` are defense-in-depth only.
- Orders: `GET /api/orders/[id]` allows owner, `role === "admin"`, or guest orders (`user_id` null) — keep that shape for the guest checkout-confirm page. `delivery_address` is stored as a raw snake_case JSONB blob (`first_name`, `address_line_1`, … — `toOrder` doesn't transform it), so order-display code must read snake_case keys. The admin order-detail page reads this public endpoint, not an `/api/admin/orders/:id` route (none exists).
- Payments/email: Paystack + Flutterwave initialize/verify + webhooks under `server/api/payments/`; Paystack webhook must HMAC-verify `x-paystack-signature` over the **raw** body (`readRawBody`), not parsed JSON, and guards amount ≥ order total (kobo) before marking paid; Flutterwave webhook checks `verif-hash`. Webhooks are the only DB writer for paid status (the confirm-page `verify` calls are display-only) and need a public URL — deployment checklist in `docs/payment-webhooks.md`. Known quirk: the verify/webhook `catch` blocks mask inner status codes as 500 — don't "fix" the amount-mismatch path, which intentionally logs + acknowledges without writing. Gateway return URLs come from `server/utils/siteUrl.ts` (`gatewayReturnBase`/`confirmUrl`): loopback hosts return to localhost, everything else uses canonical `appUrl` — never trust the Host header for production. Emails via Resend.
- Forms: `vee-validate` + `zod`; toasts via `vue-sonner` `<Toaster>` in `app/app.vue`. GA4 is hand-injected there from `config.public.gaId` with manual `page_view` on route change — don't double-instrument.
